# 可复用的作品落地页提示词

复制下面这段，替换作品名称、一句话定位和获取方式即可。先整理 Brief，等确认“开始”后再制作页面。

```text
我要为「【作品名称】」做一张官网落地页，一句话定位是「【一句话定位】」。只在 docs 文件夹里新建和修改文件，不改作品本身的代码；我说“开始”之前，不写网页代码。先读项目代码，列出真实已有的功能及使用条件，不把规划或演示写成已上线能力，不虚构用户数、好评率、效果数据或评价；再按定位写两位用户画像，每位包含“什么样的人、什么时候在什么场景使用、现在卡在哪、想要什么结果”，注明画像是设计假设，并选出三个最值得展示的真实功能，整理成 docs/brief.md。先列出页面从上到下的结构，不超过六块，每块一句话说明放什么、为什么要有，可依次考虑首屏介绍、实际效果、核心功能、上手方法、兼容与隐私、获取入口。查看 docs/images 中的图片，按实际内容使用清楚的英文文件名；保留原图比例，缺少截图就说明，示意画面必须标为示意，不冒充实际截图。收到“开始”后，按确认的 Brief、结构和图片制作 docs/index.html，所有样式与必要交互都写在这一个文件里，只使用 images 内的本地图片和相对路径，不引用网上的字体或代码库。获取入口显示「【例如：内测中，找我要安装包】」，没有真实地址就不设置下载链接，也不虚构 GitHub 链接。页面在手机上也要清楚：检查常见手机宽度，确保文字不挤出屏幕、图片不变形，主要点击区域至少 48×48 CSS 像素，实际测试导航、按钮和折叠内容，有问题直接修好，再在浏览器里打开或刷新给我看。完成后检查页面可见文案中的“最、第一、唯一、100%、永久、全网”等措辞和没有依据的数字，逐句列出、说明是否属于夸大宣传并给出改法，等我确认后再改；版本号、系统要求和步骤编号应核对依据，不当作无出处的宣传数据。所有网页与文档都不要包含 API key、密码或私人配置；未经我明确要求，不提交 Git、不上传仓库、不发布网页。交付时说明做了什么、怎样验证，以及尚未验证的限制。
```
